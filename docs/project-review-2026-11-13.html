四条关键状态链

待办

磁盘 JSON → load_app_state → React todos。用户操作先改 React，再 fire-and-forget 保存完整快照。Rust 不保存待办业务状态，没有待保存版本和失败恢复记录。

设置

React settings、Rust Mutex、settings.json、注册表和 HWND 实际状态共同参与。当前把持久化和系统副作用分开发出，没有一个统一的生效确认点。

贴边与可见性

React isEdgeHidden、Rust is_edge_hidden/pre_hide_top 与 HWND 几何分别维护。300ms 轮询探测鼠标，满足条件后收起；托盘和显示变化也可改变窗口，容易产生状态分叉。

密码锁

密码在前端经固定前缀 + 单次 SHA-256 得到 hash；hash 随 settings 保存。解锁验证、锁定标志和内容遮罩都在 React。重启读取到 hash 后会进入锁屏。

线程与生命周期

save_todos、save_settings 等都是同步 Tauri command。按官方执行模型，默认在主线程处理，因此整量序列化、磁盘写入和注册表访问可能占用 UI 调度；这是需要测量的性能风险，不是本次已经测出的卡顿。Tauri command 执行模型。

显示 watcher 在独立线程创建隐藏窗口与消息循环，再通过 run_on_main_thread 修改应用窗口；WinEvent hook 在安装线程接收事件。这种线程划分总体合理。hook/watch 句柄没有统一主动停止机制，若以后支持重初始化或多窗口，应建立生命周期所有权；当前进程级单次初始化不足以直接判为资源泄漏。

P1F01密码锁

保存并锁定后残留有效密码，可直接再次解锁

证据：src/App.tsx:303–308 · src/App.tsx:624–637 · src/components/LockOverlay.tsx:17–18 · src/components/LockOverlay.tsx:34–51 · src/components/LockOverlay.tsx:88–91

触发条件

建议修改

验证方式

证据强度：高，源码与 React 状态规则可确定。均未运行复现。 React 明确将状态与渲染树位置关联。

P1F02数据可靠性

证据：src/App.tsx:59–85 · src/App.tsx:144–158 · src/App.tsx:240–257 · src/App.tsx:638–668 · src-tauri/src/lib.rs:62–78 · src-tauri/src/lib.rs:81–105

触发条件
场景一：旧 todos.json 正常、settings.json 解析失败，启动后添加一条待办。场景二：加载被延迟时，在窗口中先提交待办或修改设置。均需隔离副本验证，不能用真实用户数据试验。
因果链
前端初始 todos=[]、settings=默认值。聚合 load_app_state 的任一读取失败都会让整体返回错误；catch 只显示消息并设置 loaded=true，输入、设置和保存函数没有 ready 门控。加载中的交互也未被禁止。后端 save_todos/save_settings 接收完整快照并替换对应文件。

建议修改

验证方式
模拟加载延迟、settings 损坏而 todos 正常、todos 损坏、读取权限失败以及显示器枚举失败。ready 之前和加载错误之后，应没有保存调用，原数据文件字节保持不变；重试成功后再启用编辑。

证据强度：高，覆盖路径明确；磁盘故障场景未运行。均未运行复现。

P2F03密码与持久化

密码设置没有等待落盘成功，失败后仍进入锁屏并隐藏错误

证据：src/App.tsx:135–142 · src/App.tsx:240–257 · src/App.tsx:303–308 · src/App.tsx:624–655 · src/components/LockOverlay.tsx:22–55

触发条件
设置或修改密码时，让 save_settings 因临时文件写入或 rename 失败而返回错误。
因果链
handleSavePassword 只等待哈希计算；handleUpdateSettings 返回 void，内部以 void persistSettings 发出保存。LockOverlay 中 await onSavePassword 并没有等待磁盘确认。内存密码先更新、界面立即锁定；持久化错误写入 App.errorMsg，但该消息只在未锁定的普通内容分支显示。

验证方式

证据强度：高，异步调用链明确。均未运行复现。

07架构、可靠性与安全风险

以下是需要补设计或验证的边界。它们没有被重复计入确认发现，也不表示已发生故障或已存在完整攻击路径。

保存语义与恢复

  • 替换写入不等于断电耐久。src-tauri/src/storage.rs:59–64 使用同目录 tmp → rename，没有 File::sync_all、备份和残留临时文件恢复。正常写临时文件或 rename 失败通常仍保留旧正式文件；突然断电后的保证尚未定义。建议根据重要性增加最后一份有效副本、坏文件隔离和恢复策略。
  • 空文件被当作全新默认状态。src-tauri/src/storage.rs:69–79 没有区分初次运行与意外空文件。建议把“文件不存在”与“存在但内容异常”设为不同结果，配合 F02 阻止静默覆盖。
  • 修改后台执行模型前先定义写序。当前同步 command 加单实例，不能仅因固定 .json.tmp 就宣称存在可达的单进程并发写坏文件漏洞。未来若改成 async/后台保存，应引入串行写入、版本确认或唯一临时文件，防止旧快照覆盖新快照。
  • 数据契约缺少显式版本。Rust settings 有 serde 默认兼容，但 theme/blur_mode 是任意字符串，todos 无 schemaVersion/迁移边界。可先加轻量校验和可读错误；不必为当前规模立即换数据库。前后端默认值目前一致，但仍是两处维护。

窗口状态与错误可观测性

src-tauri/src/win32_window.rs:325–339、src-tauri/src/win32_window.rs:476–489 和 hook/watcher 安装路径丢弃多项 Win32 返回值。部分上层命令因此无条件返回成功，还可能在实际窗口操作前先改状态。建议重要操作返回 Result，成功后提交状态；可选视觉效果允许降级，但需可诊断日志。正常环境发生失败的概率本次未测。

建议把展开、贴边收起、托盘隐藏与恢复建成一个窗口状态协调入口。不要让 React、RuntimeState 和 HWND 各自提交“成功”；由原生操作结果返回已生效状态，再同步前端。显示器变化、托盘显示和单实例唤起应复用这条路径。

DPI 与 Win+D：必须保留的实机验证项

ScaleFactorChanged 回调总是调用完整尺寸的 resize，没有显式处理收起状态；但锁定的 Tao 在 WM_DPICHANGED 处理中还可能随后应用 Windows 建议矩形。最终结果依赖回调/缓冲顺序，不能直接报告为“必然把小竖条扩大”。核对依据为 Tao 0.37.2 event_loop.rs 和 事件 runner。
